# Implementation Notes

- Workspace v2 source of truth is `packages/contracts/src/workspace/layout.ts`: `defaultWorkspaceLayout` (version 2.0.0) declares `directories` (projects, groups, groups/templates) and `seedFiles` (harnesses.json → `{"version":1,"harnesses":[]}`, settings.json → `{}`), plus `workspaceDirectories`/`workspaceFiles` path constants.
- `packages/runtime/src/workspace/bootstrap.ts` keeps the create/validate/missing-dirs API: `bootstrapWorkspace(root, {create})` → `{workspaceRoot, created, missingDirectories}`; seed files are written with fs flag `wx` so an existing file is never clobbered even under races; `validateWorkspace` additionally returns `missingFiles` and is strictly read-only. v1/PARA dirs are ignored, never removed.
- Brief assumption corrected: desktop main never consumed runtime `bootstrapWorkspace` — it has its own `ensureWorkspaceLayout` in `packages/desktop/src/main/settings.ts` (now v2 too). Unify on runtime bootstrap when PHASE-24 wires SessionStore/project store.
- Desktop settings persist in workspace-root `settings.json` (the v2 seed file). `readDesktopSettings` falls back to legacy `.command-center/config/desktop-settings.json` when settings.json is missing or still the empty seed; the legacy path is read-only. e2e app.spec and the onboarding "ready" copy updated accordingly.
- Contracts v2 modules live at `packages/contracts/src/{project,session,harness}.ts` (not under entities/). `entities/` retains only launch.ts (SLaunchContext/SLaunchTemplate — still consumed by runtime approvals/run-log and desktop terminal IPC; slated to die with the launch flow teardown).
- SessionEvent tolerance semantics: `kind` is an open `Schema.String` (a `knownSessionEventKinds` const + `isKnownSessionEventKind` guard exist for writers), `payload` is `Schema.optional(Schema.Unknown)` carried verbatim, and unknown envelope fields decode successfully and are dropped (effect Struct default onExcessProperty). `readSessionEvent` is the never-throwing reader. Property-tested with fast-check through a JSON write/read cycle.
- effect/Schema migration was import-line-only: `import { Schema } from 'effect'` replaced `from '@effect/schema'` in 9 files (contracts shared-schemas, ipc/contracts, entities/launch; runtime policy/capability, semantic-search types/config/errors/types.test; desktop pty/contracts, terminal/surface). No call-site or behavior changes; effect 3.21 core Schema is API-compatible with @effect/schema 0.75.
- Gotcha: runtime resolves @srgnt/contracts through its built `dist/` — a stale dist caused MODULE_NOT_FOUND on the deleted entities until `pnpm --filter @srgnt/contracts build` was re-run. Rebuild contracts after schema surface changes before running dependent suites.
- Terminal run logs still write to `.command-center/runs/` (services/terminal.ts mkdirs its own path — no bootstrap dependency); notes indexing still excludes `.command-center/`. Both deliberately untouched: the aggregator-era launch surface dies later, and the exclusion stays correct for old workspaces.
