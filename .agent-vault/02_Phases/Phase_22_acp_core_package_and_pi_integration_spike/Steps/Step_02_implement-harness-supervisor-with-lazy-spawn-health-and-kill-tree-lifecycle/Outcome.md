# Outcome

- Result: completed. `packages/harness/src/supervisor/` manages agent child processes as pure Node (`@srgnt/harness`, zero Electron, boundary-enforced): an explicit single-use state machine `idle → spawning → ready → reaping → dead` (`HarnessProcess`), lazy coalesced `start()`, stderr-ring crash tails, process-group kill-tree that leaves no orphaned grandchildren, and a multi-process `Supervisor` with lazy `ensureRunning`, idle-reap, capped-backoff restart with typed give-up, and `disposeAll` for app quit. Composition with STEP-22-01: `Supervisor.spawnerFor(id)` returns the `AgentSpawner` that `AcpAgentConnection.connect({ spawn })` already accepts, and `HarnessProcess.transport` is a `SpawnedAgent` (ndJsonStream over the child's stdio) — the supervisor is the "real spawner" the connection layer was designed around.
- Kill-tree per platform: POSIX signals the process group (`process.kill(-pid, sig)`; child spawned `detached: true` so pgid == pid), SIGTERM → grace (default 5000ms) → SIGKILL, ESRCH swallowed, EPERM falls back to single-pid. Windows best-effort `taskkill /pid <pid> /T [/F]` (SIGKILL adds `/F`), not first-class but not designed out.
