# Implementation Notes

- **Scenario injection seam** is `resolveMockScenarioPath(override = process.env.SRGNT_MOCK_SCENARIO)` in `packages/desktop/src/main/chat/session-controller.ts`, exported alongside `MOCK_SCENARIO_ENV`. Unset ⇒ the built-in `MOCK_DEMO_SCENARIO` written once per process into a temp dir (unchanged behavior). Set ⇒ that file, after an `existsSync` check that throws a readable error — a missing scenario would otherwise become `exit 2` inside the spawned bin, which the supervisor reads as a crash loop.
- The old `cachedMockLaunch` memo was dropped; only the *default scenario path* is memoized now. `mockLaunchSpec()` is cheap (`require.resolve` + string joins) and must be re-read per session so an env-injected scenario is honored.
- **Agent-side assertions need a channel out of the spawned process.** The mock's `expect_prompt` / `expect_cancel` / `expectOutcome` / `expectOptionId` failures previously landed only in `MockAgent.assertionErrors`, which is unreachable once the agent is a child process — so from an E2E driver they were invisible and effectively dead. Added `RunnerHooks.onTurnEnd(assertionErrors)`, awaited in `prompt()` *before* the `PromptResponse` is framed, and wired in `bin.ts` to `--assertions <path>` (`writeFileSync`, synchronous on purpose: a driver that sees the turn finish is guaranteed the file is already written).
- `mockLaunchSpec()` always passes `--assertions <dirname(scenario)>/mock-assertions.json`. For the built-in demo that is a throwaway file in a temp dir; for E2E it lands in the test's `userDataDir`, which is where the `agentAssertions` fixture reads it.
- **Carry-forward from STEP-23-03 closed:** `request_permission` now carries optional `kind`, `locations`, and `rawInput` (`scenario.ts` + passthrough in `runner.ts`). Before this every mock-driven prompt normalized to `kind: 'other'` with the title-scope fallback, so path and command scoping had host-level tests only. `e2e/chat.spec.ts` now proves both shapes render: `kind: 'edit'` + `locations` → the path in `chat-permission-detail`; `kind: 'execute'` + `rawInput.command` → the command.
- **Playwright wiring:** `mockScenario` is a Playwright *option* fixture (`test.use({ mockScenario })`), written to `userDataDir/scenario.json` by the `electronApp` fixture and injected as `SRGNT_MOCK_SCENARIO` through `getElectronLaunchEnv(userDataDir, extra)` (second parameter added; existing callers unaffected). Scenarios stay test-local, so nothing is shared or ordered between tests.
- `disableAnimations()` **cannot be used in chat specs**: the renderer's CSP is `style-src 'self' 'nonce-srgnt-renderer'` and `page.addStyleTag` is refused with a CSP violation. Every wait in `chat.spec.ts` is an `expect(...)` poll on a locator instead — no screenshots, so nothing needed it.
- A finished thought block auto-collapses (`ThoughtBlock` sets `expanded = userChoice ?? streaming`). The streaming test waits for `data-streaming="false"` and clicks the toggle rather than racing the open window.
- Tool-call bodies (including diffs) are behind the card's `chat-tool-call-toggle` disclosure, collapsed by default.
- The `pending` → `completed` transition is only observable because the scenario inserts `{ type: 'sleep', ms: 400 }` between the `tool_call` and its update. Without it the two frames arrive in the same rAF flush and "lifecycle" would be untestable.
- A crashed agent is **not** auto-respawned: `Supervisor` restarts lazily, on the next spawn request. So `status: 'crashed'` is terminal for the renderer and the `chat-agent-down` banner does not flicker back off mid-assertion.
- **Negative control run** (throwaway spec, deleted after the run): a scenario with a deliberately wrong `expect_prompt` and a wrong `expectOptionId` produced exactly those two failures through `agentAssertions()` and failed the test. The channel is live, not vacuously empty.
- **Vitest limit confirmed (carry-forward from STEP-23-04):** `defaultChatConnect` still cannot run under vitest (`Function('return import("@srgnt/harness")')` → `ERR_VM_DYNAMIC_IMPORT_CALLBACK_MISSING`). That is why the seam is unit-tested through the exported pure `resolveMockScenarioPath`, and the real spawned-process path is proven by `chat.spec.ts` against the built `dist/` plus the harness subprocess test.
- **Pre-existing local E2E failures, not caused by this step:** `app.spec.ts › exercises preload APIs…` fails with `posix_spawnp failed` from `terminal:launch-with-context` (node-pty cannot spawn on this machine), and `bug-0013-visual.spec.ts` hardcodes `release/linux-unpacked/srgnt`, so it can only run on Linux after `pnpm pack`. Both fail identically without this step's changes.
