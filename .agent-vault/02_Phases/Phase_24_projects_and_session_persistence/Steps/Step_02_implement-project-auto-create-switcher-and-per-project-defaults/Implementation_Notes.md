# Implementation Notes

- Identity: `deriveProjectId(rootDir) = sha256(path.resolve(rootDir)).slice(0, 12)` in `packages/runtime/src/projects/paths.ts`. `path.resolve`, never `realpath` - a symlinked checkout stays its own project. Collision is handled, not avoided: `ensureProjectForDir` compares the stored `rootDir` and throws `ProjectIdCollisionError` on a mismatch, so the slice length is a tunable rather than an invariant.
- Create-once: `ProjectStore` keeps a per-id promise-chain lock. Concurrent `ensureProjectForDir` calls for one directory produce exactly one record and every caller sees the same `createdAt` (asserted in `store.test.ts`).
- A corrupt/partial `project.json` is REPAIRED (rewritten) rather than rejected: it carries no trustworthy `rootDir`, so nothing can be stolen by rewriting it, and rejecting would wedge the directory permanently. Leftover `project.json.*.tmp` scratch files are swept at the same time. Only a *valid* record with a different `rootDir` fails closed.
- Merge journal (`projects/<targetId>/merge.journal.json`) is written BEFORE anything moves and carries the source's `rootDir` + `additionalDirectories`, because a later step deletes the source `project.json`. It deliberately does NOT track `movedSessionIds`: recovery re-reads whatever is still under the source, which is idempotent and self-correcting, and saves an fsync per moved session. `recoverMerges()` runs from the projects service on every workspace-root change and never throws.
- Atomic writes were de-duplicated: `packages/runtime/src/shared/atomic-json.ts` (`writeJsonAtomic`) now backs both `writeSessionMeta` and `project.json`.
- The permission engine needed no change - STEP-23-03's `projectPolicy` hook was already the seam. `createProjectPolicyHook` (`projects/policy.ts`) maps a stored `allow`/`reject` to a decision and returns `undefined` for `ask`, unknown kinds, and no policy. It uses `Object.prototype.hasOwnProperty.call` because `request.kind` is agent-supplied and a bare lookup would resolve `__proto__`/`constructor` off `Object.prototype`.
- `chat:session:new` resolution lives in `packages/desktop/src/main/chat/index.ts`: `projectId` -> `projects.get`, else `projects.ensureForDir(cwd)`. `resolveChatTarget(requested, defaultHarnessId)` prefers an explicit target, then the project default when it names a harness this surface can drive, then `mock`. A project whose `rootDir` no longer exists rejects session creation with a readable message instead of handing the agent a bad cwd.
- The switcher's real home is the chat panel's side-panel content (`ChatPlanSidePanel`), as the corrected orientation in the brief says - NOT `Navigation.tsx`/`AppLayout`.
- **Gotcha worth remembering:** the active project must default to the project whose `rootDir` IS the workspace root, or `null`. Preselecting `projects[0]` silently redirects session creation and broke all 8 Phase-23 chat E2E specs when that project's directory had been deleted. Regression test: `ProjectSwitcher.test.tsx > active project selection`.
- Desktop E2E used to onboard into the developer's real `~/srgnt-workspace` (`completeOnboarding` clicks "Use Default Location"). Fixed during PR review: `resolveDefaultWorkspaceRoot` honors `SRGNT_DEFAULT_WORKSPACE_ROOT`, and `getElectronLaunchEnv` points it under each test's own user-data dir, so every spec is isolated by the fixture. `e2e/projects.spec.ts` additionally re-roots at runtime via `setWorkspaceRoot`.
